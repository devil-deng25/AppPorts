# Agent Note: 签名原包自动保存到外盘的可见目录

Status: implemented

## Problem

AppPorts 的核心目标是减少内盘占用，但历史实现把重签名前的完整官方应用放进内盘 `~/Library/Application Support/AppPorts/signature-backups`。应用搬到外盘后，备份又占回约一份应用的空间。跨卷复制无法使用 APFS clone 消除这份占用。

保留完整原包仍有价值：只保存证书名称或 `_CodeSignature` 目录不足以恢复重签时改写的 Mach-O 和嵌套代码。需要改变原包位置并去掉重复复制，同时保留现有恢复、依赖检查和中断续作能力。用户不应为了管理这些原包增加一次目录选择或学习新的管理界面。

## Decision

新的长期原包统一存到自动选定的外盘根目录 `AppPorts Backups`。目录在 Finder 中可见，内含中英文 `README.txt`，解释用途、恢复入口、手动删除的后果和空间口径。说明文件首次创建后不覆盖用户编辑。内部 `signature-backups` 只承担小型索引和旧格式兼容；签名事实和操作记录仍留在内部。

自动选择按应用所在外卷、已有 `ExternalDrivePath` 所在外卷、其余可写且容量充足的本地外卷依次尝试；其余外卷以剩余容量排序。内盘、网络卷、只读卷和磁盘映像不参与选择。创建目录前重新核对卷 UUID、内外属性和可写性。无可用外盘时，在修改正式应用前停止，永不回退到内部长期备份。

不增加备份设置、文件夹选择器或管理页面。用户在 Finder 浏览或删除原包，在既有应用操作中使用“恢复原始签名”；AppPorts 自动完成已授权操作、迁出仍有用的内部原包并清理已证明冗余的材料。

## Retention and recovery protocol

- 带证书的原应用必须先取得开发者事实并通过严格验签，才能创建签名候选。读取失败、验签错误或超时直接停止，不能按“没有官方原包”继续重签并删除原件。
- 签名候选仍放在真实应用同级 `.AppPorts-signature-<UUID>`，以同卷原子交换提交。外盘上的应用也直接在外盘工作，不要求先迁回本机。
- 应用与备份目录同卷时，交换留下的原件用独占 rename 转为长期原包，保留 inode，不再复制第二遍。跨卷时完整复制、核对指纹和开发者、同步原包与目录、发布索引后，才清理原位置。
- 签名备份和保存义务使用 schema 3。原包目录、应用父目录以卷 UUID、卷内相对路径和目录 inode 绑定。挂载点名称变化后按这些事实寻找；同名目录、替代卷、符号链接都不能继承保存或删除权限。
- 已知原包离线、损坏或正在迁移时，再次重签不能静默丢掉恢复关联。schema 3 参与后续签名事实更新，使新的已验证签名指纹仍可对应原包。
- 同一版本的重复重签继续引用最初保存的官方原包，不用已重签的包覆盖它。只有经过身份验证的官方新版本才建立对应的新原包。
- 未完成的新原包保存事务可以按已保存的应用父目录定位重挂载后的工作区，再核实应用与候选身份。更新保护只迁移既有路径提示和已记录的锁来源，不借重挂载采用未知锁。
- 复制完成的收据不是永久的删除许可：冷启动续作及最后一次删除内部原件之前，都重新验证外盘原包仍在且内容完整。
- writer capability 升为 v5，旧写入进程不能忽略新的原包位置及保存义务。
- 已报错撤回的未提交签名先持久标记 `cancelling`，再检查写入兼容性并清理候选；初次状态写入失败时，后续补记仍保留取消意图，不能让自动维护重新提交。进程中断留下的合法 prepared 记录仍可续作，同类操作在确认候选已安装后返回原提交结果，不重新签名，也不因迟到取消丢弃已提交状态。

## Legacy originals and cleanup

schema 2 完整原包继续可恢复。自动维护先判断当前安装是否已经恢复原版或成为经过身份验证的同开发者官方后继；无签名、应用转移及容器数据依赖时，才按已有清单退休。

仍有恢复价值的内部原包自动迁到外盘。迁移检查点保存在原来的小型索引中：记录源目录、源对象、目标位置及删除清单；复制并验证外部原包后，持久发布 schema 3；最后按清单移除内部源包。复制中断、发布后中断及部分删除均可继续。源包不是根据名称或存在时间认领的。

旧版只有身份名称的记录不能恢复签名字节。完整原包已不存在的索引也不能算可恢复副本。没有待续操作依赖，且独立签名事实已保留同开发者、同来源信息，或当前安装已验证为对应的官方应用时，自动清理这类记录。事实先持久化，再删除索引。无法关联当前安装的旧记录保留：它们很小，不能为清理几个 KiB 而编造已恢复或丢掉唯一的来源信息。

外盘未接入与原包实际缺失严格区分。未知来源的大目录、损坏记录、内容被改动的原包均不按年龄批量删除。Finder 明确删除可恢复原包会丢失这一份离线恢复能力，不影响当前安装及用户数据；说明文件明确这一点。APFS 共享块和废纸篓意味着显示体积不等于立刻释放的空间。

## Signing actions and login setting

应用列表已确认 `isResigned` 时，菜单保留“恢复原始签名”并隐藏重复的“重签名此应用”。官方更新使应用回到官方签名后，重新显示重签入口。检查结果未知时不伪装成已重签；显式操作仍由服务重新检查真实安装。底层保留重复签名的来源保护和同类事务续作，用于恢复中断以及需要重新生成签名的服务调用。

`AutoResignInstaller.supportsLoginResigning` 对所有系统版本都返回 false，设置中的“开机自动重签名”和仅 macOS 27 不支持的说明已失真。移除这张常驻卡片，保留旧登录任务的中和、停止和卸载流程；仅当卸载实际失败时显示现有错误与重试动作。

## Alternatives considered

- **固定内盘**：原包不依赖外盘在线，但抵消释放内盘空间的目标，尤其应用已经迁出时。
- **原包跟随应用同卷**：普遍可改名保留，未迁移的本地应用却仍留下内部长期原包，不符合产品目标。
- **不保存长期原包**：空间和生命周期成本最低，恢复必须取得官方原件或重新安装。本次选择维持离线恢复能力。
- **身份信息、签名目录或反向差分**：前两者体积小但不能完整恢复；反向差分可行，却引入基线、格式和重建校验成本，本次不采用。
- **压缩原包**：可能省空间，但许多应用资源已压缩，还增加解压与验证的阶段。
- **用户选择备份位置**：灵活且能表达盘的偏好，但与省内盘的默认行为重复。本次自动选择并复用现有外盘线索。
- **隐藏目录加管理入口**：能集中呈现状态，但增加页面和维护；用户希望直接看见文件，因此采用可见目录加说明文件。
- **不可恢复记录全部删除**：简单，但一部分名称记录仍是判断历史签名来源的唯一信息。仅删除已有独立来源事实或已验证官方状态的记录。

## Testing

2026-10-15，在 macOS 27、Xcode 27.0 环境完成验证：

- 签名、原包存储、恢复、旧原包退休、迁移集成及挂载边界共 13 个 Swift Testing suite、167 个测试通过；`AppTransferTransactionTests` 的 57 个 XCTest 和 `LocalizationAuditTests` 的 10 个 XCTest 通过。新错误和确认文案覆盖全部 22 种语言。
- `WriterAdmissionTests` 最终独立运行 17 个测试通过。首次回归的一个夹具失败源于 macOS 将复制出的平台签名 `/bin/sleep` 杀死；独立复现 SIGKILL 后，仅给可丢弃夹具做 ad-hoc 签名并断言子进程存活，再测试 writer 准入。没有放宽生产准入检查。
- 原包存储测试覆盖自动选盘与排除、目录替换、README 保留、真实不同卷与重挂载、重复签名、旧格式恢复、schema 2 复制中断及发布后的部分清理。可丢弃 APFS 映像用于验证真实文件系统行为。
- 最终源码通过 Release `xcodebuild clean build`，scheme 为 `AppPorts`、destination 为 macOS；沿用本机既有开发签名身份，将 1.9.1 build 31 安装到 `/Applications/AppPorts.app`。安装包通过严格验签，完整文件指纹与构建产物一致，挂载任务的程序路径与签名标识均对应这个安装包，运行进程声明 writer v5。
- 从安装后的 AppPorts 界面对内盘 IINA 1.3.5（141）完成重签与恢复：外盘 `AppPorts Backups` 中的 schema 3 原包与重签前 1,233 个文件、164,072,969 字节内容逐项一致，内盘临时原件已移除。恢复后的完整指纹与基线一致，Hechen Li 的官方签名通过严格验证，原包与索引自动退休。
- 对外盘 PortKiller 连续重签两次：第一次保存保留原件 inode；第二次后原包路径、inode、保存时间、开发者和内容指纹均不变，只保留一份官方原包。恢复后 107 个文件、21,607,191 字节与最初基线一致，Mehmet Kalayci 的官方签名通过严格验证，原包与索引自动退休。
- 最终安装包的界面确认：已重签时隐藏重复重签动作，恢复后重新显示重签入口；设置页没有失效登录签名开关、备份管理页或正常状态下的清理错误提示。
- 实际清理一份与已安装 Agents Anywhere 完全相同且签名有效的孤立候选，清理前复核内容、inode、待续事务和打开句柄。其逻辑内容约 1.60 GB，`du` 报告约 1.50 GiB；APFS 共享块使这个数字不能当作实际释放容量。内盘旧索引最终保留 15 份、共 7,622 字节内容，没有完整 `.app` 原包；这些记录不能凭年龄当作无用来源删除。

早期实机验证暴露过两个关联缺陷：临时目录中的新 GUI 与已安装旧挂载任务的 writer 能力不一致；准备失败的事务未持久标记取消，之后被自动维护提交。最初的官方验签失败又被吞掉，不能从残留日志断言其具体成因。IINA 曾因此进入无保留原包的 ad-hoc 状态；从官方同版本 DMG 取得与测试前完整指纹完全一致的原件后恢复，再执行上述成功的外盘备份往返。严格验签拒绝、准入失败后的持久取消（包括首次状态写入失败）、冷启动续作及迟到取消均已有回归覆盖。

## Consequences

长期完整原包移出内盘，用户直接在 Finder 查看外盘目录与说明文件；同卷保存不再复制第二份原件。安全迁出及自动退休仍承担完整内容校验和依赖检查的成本，重复签名不会为节省成本改写最初官方来源。只有外盘空间或校验成本成为新的实际瓶颈时，才重访压缩或差分格式。

没有合适外盘时，新的官方原包重签在修改正式应用前停止。未迁出的应用仍需要一份操作期内部候选，跨卷原件在确认外盘持久成功前也会暂留内部。外盘故障会同时影响放在该盘的应用和原包；这是释放内盘空间的恢复材料，不是独立灾备。

目录不得随意移动，已有记录按保存时的卷身份查找，不随当前自动选盘结果改写。来源无法核实的几 KiB 旧记录继续保留。磁盘映像和已连接物理外盘测试不等于 USB 热拔插或设备断电验证；真实官方新版替换后的自动退休不能由本次同版本恢复测试代替。
