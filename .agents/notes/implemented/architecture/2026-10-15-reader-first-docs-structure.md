# Agent Note: 面向普通用户的文档目录与内容深度

Status: implemented

## Problem

原中文站的 31 篇正文混合了操作、底层机制和故障诊断。数据迁移分散在基础实现、工具识别、挂载、签名和身份页面；FAQ、故障排除与日志又重复部分内容。普通用户为完成一次迁移，需要先辨认技术类别。

实验篇幅过长，旧文将有限样本概括为普遍规律；设置、签名、默认迁移方式也与当前开发版本存在偏差。精简不能丢失必要限制和历史功能，旧应用帮助链接仍需可用。

## Decision

中文正文按 AppPorts 1.9.1 开发版的实际代码和界面整理，明确与已发布 v1.9.0 区分。操作、原理、实验和参考条目各自承担不同阅读任务，目录最多两层；不要求用户先研究内部机制或运行终端命令。

主目录包含 25 篇，顺序由 User_docs/config/docs-navigation.json 唯一描述：简介、快速开始、迁移应用、迁移数据、还原／接回／解除链接、外置盘与日常使用；原理组五篇；实验组六篇；帮助与支持两篇；设置、更新日志、赞助、开源许可、隐私政策、词汇表。没有“使用指南”分组，词汇表是主目录最后一项。

简介保留产品介绍、文档用途、DeepWiki 参考与作者博客来源链接，以及透明体验、策略稳定、低系统负担、广泛国际化、无障碍友好五项产品哲学。政策与许可保留完整条款和主目录入口，贡献者指南作为辅助页保留开发细节。另有四篇历史归档，共 30 篇中文页面。

### 正文与版本边界

操作文章说明适用范围、准备、步骤、可观察结果和问题入口。原理集中在一个分组，不把内容堆成一篇长文。术语首次出现时给必要解释，再链接词汇表或主解释文章；链接不能代替必需步骤。

按钮按当前界面核对：应用使用“迁移到外部”“迁移回本地”，删除入口是行末垃圾桶；默认容器“迁移”执行挂载流程，经典模式下才单列“挂载迁移”。准备情况检查权限、连接、格式和加密，本次容量与安装位置以操作检查为准。

当前迁移与手动签名分开，所有系统停用登录自动重签。恢复原始签名与再次重签不同；官方覆盖安装外置应用前先迁回，完整备份或匹配原件可直接修复外置应用。签名待检查不能等同于签名损坏，签名已替换也不证明数据损坏。未加密 APFS 的强制要求仅用于相应容器挂载迁移。

### 历史功能归档

archive/overview 作为索引，data-signing 保留旧容器链接、迁移后重签、登录自动重签、旧身份记录与恢复材料的演进；app-strategies 保留 Contents、整体符号链接、启动壳变化和默认关闭的透明混合原型；mount-experiments 保留磁盘映像、fstab 和系统守护进程等未采用实验。

归档标题与正文标注状态、适用阶段、停用原因和当前替代入口。整体符号链接仍有“使用传统链接迁移”手动入口，不能被误标为完全停用；实验原型也不能描述成曾经正式提供的功能。早期 Sparkle Hybrid、Electron Hybrid 的结构与当前默认关闭原型分别记录。更新日志保留历史条目，在已停用的自动签名条目旁增加归档说明。索引可从首页页脚、更新日志、经典模式、原理和词汇表访问，不占主目录的最后位置。

赞助留言说明增加 mailto:a@shimoko.com，供修改昵称、链接和其他展示信息；赞助者 JSON、金额、顺序、二维码与公开规则不变。

### 实验与公开边界

六篇实验采用问题、条件、过程、结果、意义、限制的结构，不发布调查对话、个人路径、账号、原始日志包或内部笔记链接。保留失败与中止结果；新实验只整理已有材料，没有执行新的拔盘、重启、真实数据迁移或系统授权修改。

### 路由与生成契约

保留沿用文章的 URL。11 个合并源文件退出正文与搜索，旧 URL 通过 config/legacy-links.json 映射至当前主题或相关历史页，包含原自动标题 ID 和显式 ID。正文的固定章节 ID 转换为 Fumadocs 原生 [#id]，由实际标题持有。旧章节 ID 作为不可见锚点插入对应新章节前；同名 ID 若属于不同目标则构建报错，不能静默跳过。更新日志重复的“改进”等章节按版本固定 ID 并逐项映射，检查验证旧锚点后紧接的具体标题。

合并页 /docs/<旧路径> 参与 Next 静态参数生成，显示 noindex/canonical 并由客户端 router.replace 转到实际文章，保留查询参数并映射旧 hash。根目录的旧 .html 文件使用同一个解析函数生成跳转脚本。没有 JavaScript 时仍提供目标文章链接。本地 serve 预览对 .html 禁用自动去扩展名跳转，避免服务器先丢掉查询参数；根首页和无扩展名页面仍可访问。未知或损坏 hash 回退到该旧页的主目标，不制造无效章节。

导航描述同时约束来源清单，并用于 source.pageTree 的结构转换，侧栏、分类与上一页／下一页使用同一棵树。辅助页可被搜索和直接打开，但不改变主目录顺序；历史文章的标题和正文显式标记归档。

七种其他语言的187个源文件保持原字节内容。语言按钮优先打开线上同路径译文；新拆分主题通过 config/language-links.json 关联旧译文及现有显式章节，如经典模式到 settings#classic-data-migration-mode。无同路径或相关译文时才回语言首页。Markdown导出保留表格、提示与流程图源码，去掉仅供网页兼容的锚点标签。

## Alternatives considered

- 只把现有技术页移到“原理”：迁移成本最低且保留全部材料，但不能解决操作与原理混写、版本错误、术语重复和实验叙事过长，因此不足以满足本次目标。
- 把所有技术内容压成一篇原理长文：顶层入口最少，但应用迁移、数据迁移、徽章和经典模式的阅读任务不同，会重新形成难检索的长文；采用一个一级组和五篇短文章。
- 操作和实验全部混排在同一组：相关内容看似集中，但普通用户难区分建议操作、历史实验和验证局限；使用独立实验组并通过链接关联。
- 一次重写八种语言并重命名全部路径：结构最一致，但会扩大翻译、链接兼容和主分支协作范围；本次中文先行，稳定 URL 尽量沿用，译文切换保留线上方式。

## Consequences

正文按任务可直接阅读，原理、实验与历史功能仍可查阅；当前和旧版行为得到区分。章节兼容映射与内容转换增加维护成本，后续标题或职责变化必须同步目标并运行检查。精简旧实现细节不能删除失败证据或停用功能的必要说明。

目前仅中文采用新结构，线上译文保留原目录和外观；当前开发版本与正式版本也存在差异。发布新版本或扩展多语言时需重新核对版本说明、词汇与路由，不能将本次中文预览直接替代线上八语站点。

## Verification

构建、类型检查和 docs:check 验证30篇正文、25篇主目录、11个合并地址及旧章节映射、Markdown可读性、固定锚点、导航和归档契约，以及 sponsors.json/latest.json 原样输出。实验与界面事实经独立只读审查；普通操作中的权限检查位置、签名恢复分流及按钮文案按实际代码修正。

Playwright 检查旧 .html 与 /docs 地址跳转、查询参数和中文锚点、搜索、新实验、归档标识、语言回退、复制 Markdown、等高按钮、赞助邮箱、主题、桌面与手机目录。仓库要求的 Release clean build 在独立 DerivedData 中通过，应用代码未修改。七种译文逐文件校验；合并检查以当时 main 提交和未提交路径为准，不覆盖主工作区。
