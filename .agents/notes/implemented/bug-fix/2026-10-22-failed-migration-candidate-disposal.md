# Agent Note: 自动丢弃从未启用的失败迁移卷

Status: implemented

## Problem

Issue #81 在复制期间打开企业微信后校验失败，原数据入口已恢复，但清理仍要求原目录等于复制前清单。应用的正常写入因此令失败事务永久留下候选卷。重试间隔只能减少重复读盘，不能消除这个错误前提。

## Decision

挂载迁移中，原目录身份仍成立或有已完成后继证明当前有效位置时，操作独占、从未尝试启用的候选卷可以丢弃，包括候选内的新增内容。原目录的新写入保留。可丢弃候选的收尾只同步原入口目录，不遍历或重写源内容；应用新建的不可读子目录不能阻止丢弃从未启用的副本。其他需要冗余证明的路径仍同步完整当前数据。卷 UUID、创建容器、候选根与父目录身份、操作专属路径、无其他记录引用、无写入者仍必须在删除前成立。还原暂存、已启用目标与未知孤儿不适用。

新挂载迁移以 schema 12 保存可选 `candidateActivationAttempted`：开始为 false，普通和冷恢复路径在首次向原入口挂载前持久写 true；true 不能清空或改回 false。保存失败不得启用。旧记录缺字段仍保持未知，不按当前阶段或挂载位置推测历史。仅对有准备基线和目标归属、无完成基线且无备份身份的旧复制事务，依据旧版本“完成基线先落盘、再启用且不回退清空”的不变量证明从未启用。

准备取消与回退后清理共用卷删除路径；入口恢复优先，删除失败保留同一操作供退避重试。删除前记录父目录凭据；验证后被移除的私有占位使用独立的 `candidateRemovalMountPointIdentity`，不覆盖原准备身份。硬中断留下未记账的空占位时，只在原父目录、操作专属路径、非挂载且非软链和空内容全部成立后重新认领；带数据的替换目录不适用。该占位事实可以作为历史证据随成功提交保留。卷已不存在时必须由在线原容器的完整列表确认，随后清理自己的空占位并补记账。升级不把未知历史卷转换为可删对象。即使占位已经消失，有删除检查点的重试仍检查并同步原父目录。删卷在最后设备查询后复核未挂载、当前源身份与账本独占引用；管理员重试也重复该检查。管理员密码等待结束后，在授权进程内再次查询精确设备、UUID、APFS 与未挂载状态，校验源/父目录的设备号与 inode 以及整个账本的 SHA256，再执行固定删卷命令。账本摘要绑定等待前的引用与用户选择，源只绑定身份以允许新写入；授权进程不修改账本，参数全部按单引号引用。

## Reconnection at the system automount

实盘拔盘后，macOS 会把候选重新挂到 `/Volumes/<卷名>`，并分配不同的设备号。此落点只允许有从未启用证明、完整卷标记、UUID 与根 inode 以及账本独占归属的候选脱离；系统挂载父目录、源身份、应用和卷写入者也需复核。随后仍回到操作私有位置，经过原有校验和删除授权，不直接按名称删卷。额外检查自动挂载路径与其他账本路径的重叠；任意其他落点或已尝试启用的目标仍保留。测试可注入自动挂载根，全部假卷限定在临时目录。

候选卸载绑定精确设备号、UUID 和当前挂载路径。普通与管理员重试均先复核；授权脚本在密码窗口结束后检查相同事实、源及候选根/父目录身份和账本摘要，才非强制卸载该设备。共享脚本使用系统实际提供的字符串 `MountPoint`：卸载要求等于当前路径，删除要求为空；字段缺失或类型错误拒绝操作，不依赖部分系统没有的 `Mounted` 字段。

`rolledBack(retainedDetails:)` 带有原因时，维护调用把该原因返回任务中心，同时保留退避记账。恢复入口成功不再吞掉后续清理失败，手动重试不会误报“已完成”。任务中心旧历史仍是当时操作结果，不替代当前恢复账本。

本分支复用[按卷事件核实落点](2026-09-23-event-driven-container-remount.md)的身份检查原则；该篇与本篇部分重叠，无需取代或归档。

## Alternatives considered

- **继续比较候选与旧源清单**：能保护未知副本，但在从未启用、用户已同意丢弃的操作产物上把正常源写入变成永久残留。
- **只凭入口已恢复或私有路径删除**：容易覆盖更多历史残余，但重启可能隐藏曾启用的目标，无法保护其独有数据。
- **只支持新字段，所有旧记录保留**：实现简单，却无法解决已有 #81 类事务；只接纳旧代码持久化顺序能够证明的未验证候选。

## Consequences

必须维护所有启用入口的提前记账；schema 12 不能承诺被旧客户端理解。明确可丢弃的失败卷会失去操作期间写入其中的内容，这是用户选择的语义；当前源数据、已启用目标和未知材料的保护不降低。模拟测试不能代替实盘断电实验。

独立审查发现并修复了占位认领失败后的冷恢复、历史占位凭据阻断后续成功提交、缺失占位的同步屏障重试，以及最后查询和管理员授权等待窗口的复核缺口。扩展回归中旧的“失败后账本完全不变”断言只放宽重试计数与时间字段；身份、内容基线、阶段、拓扑和实际文件保护断言保留。
