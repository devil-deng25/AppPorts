# Agent Note: 迁移应用时一并迁移它的关联数据

Status: implemented

## Problem

「应用迁移」此前只搬外盘上的 `.app`，`~/Library/Application Support`、`Caches`、`WebKit`、`HTTPStorages` 里的应用数据仍留在本机。用户看到应用已经在外盘、空间却几乎没减少，还以为数据一起搬走了；想真正腾空间必须再切到「数据目录」页，对着几十个目录逐个找、逐个迁。两个页面之间没有任何提示说明它们是一件事的两半。

## Decision

新增 `AppCompanionDataMigration`，在应用本体迁出成功之后，紧接着迁移该应用的关联数据目录。开关是 `MigrationPreferences.shouldMigrateCompanionData`（`migrateAppCompanionData`，默认开启，用 `object(forKey:)` 区分「未设置」与「显式关闭」）。

准入条件写成白名单，不做「尽量多搬」：

- 只处理 `applicationSupport`、`caches`、`webKit`、`httpStorages` 四类。容器与组容器需要挂载迁移，不属于同一条路径。
- 只处理本地状态（`DataDirStatus.local`）、可行（`isMigratable`）、路径策略允许（`pathPolicy?.canMigrate != false`）的项。
- 跳过微信账号拆分的成员目录（它们由拆分流程持有）、跳过空目录。
- 需求挂载迁移或当前处于挂载状态的项记入 `mountRequired`，不改状态、不尝试迁移。

迁移复用 `DataDirMover.migrateAndComplete`，逐项执行，单项失败只记录不中断；取消时先检查 `Task.isCancelled`。应用本体迁移与数据迁移共用同一个后台任务与进度条，任务标题按是否携带数据在「正在迁移应用」与「正在迁移应用与数据」之间切换。设置页新增「迁移应用时一并迁移数据」开关，说明里写明沙盒容器仍归「数据目录」页。

结果消息按三种情况拼：全部成功不加话；有失败项报「应用已迁移，但有 %d 个关联数据目录未迁移（%@）」；遇到容器则报「应用已迁移；%@ 属于沙盒容器，需要挂载迁移」。

## Related decisions

- 与[容器卷改为挂载事件驱动](../bug-fix/2026-09-23-event-driven-container-remount.md)部分重叠：容器数据仍然走挂载迁移，本篇只把「不需要挂载的那部分」并进应用迁移，并明确指出容器不在范围内。
- 与[应用数据目录身份](../bug-fix/2026-09-29-app-data-identity.md)部分重叠：数据目录的身份判定、冲突保护、可续清理全部沿用，本篇只决定「什么时候顺手触发一次迁移」。
- 与[经典数据迁移模式](../architecture/2026-10-09-data-ownership-compatibility.md)无交集：本篇不改变符号链接与重签名的准入规则。

## Alternatives considered

- **把容器与组容器也塞进这条路径**：用户一次点击就能全搬完，看似更省事，但容器必须走挂载迁移，混在一起会把「复制」和「挂载」两种失败语义混在一个进度里，回滚也更难。放弃。
- **默认关闭，让用户在设置里手动打开**：行为变化更保守，但用户仍然要自己发现这个开关，等于没解决「两个页面是一件事」的认知问题。
- **迁移完提示用户去「数据目录」页自己点**：实现成本最低，也是现状的做法；已经证明没人会去点。
- **把所有 `~/Library` 下同类目录按 bundle id 模糊匹配全搬**：覆盖更全，但误伤风险高（同名前缀的目录未必属于这个应用），且与 `DataDirScanner` 的既有匹配规则冲突。

## Consequences

一次「迁移应用」现在默认会连带迁走四类数据目录，释放的空间与用户预期一致；不需要这些数据一起走的用户可以关掉开关。代价是应用迁移耗时变长（数据目录通常比应用本体大一个量级），因此进度条复用同一套 `FileCopier.ProgressHandler`；失败项不再回滚已完成的项，而是明确报出数量并把剩下的交给「数据目录」页重试。

默认开启意味着一次迁移会触碰更多路径，所以准入条件写得比「数据目录」页更保守：只碰本地、可迁、策略允许、非空的四类目录，容器一律不碰。

## Verification

本机没有 Xcode（只有 Command Line Tools，`security find-identity` 为 0 个有效身份），因此没有执行 `xcodebuild clean build`，也没有运行 `DataDirMoverTests` 与 `AppMigrationServiceTests`。已用 `swiftc -typecheck` 覆盖服务层文件；`swiftc -parse` 覆盖改动的视图文件。实际迁移（含失败项与容器跳过两条分支）需要在装有 Xcode 的环境里用真实外盘复验。
