# Agent Note: 挂载类命令改由常驻特权助手执行，一次授权长期有效

Status: implemented

## Problem

「一次授权，永久有效」在 `do shell script … with administrator privileges` 这条通路上做不到：
AuthServices 的凭据挂在发起进程上，空闲约 5 分钟后失效，进程退出即消失。应用没有任何地方
可以保存它。结果是每次挂载容器卷都要再输一次密码，成批整理数据目录时会被连续打断。

同时，「要 root」的范围比实际需要的大：应用入口交换（`--privileged-app-transfer`）、
`chown -R` 修所有权、卷的创建与删除、以及挂载，全部走密码框。其中只有挂载是**反复发生**的。

## Decision

把 root 场景收缩到挂载一类，再用一次安装把这一次性成本摊平。

**范围收缩。** 删掉 `CodeSigner.ownershipRepairAppleScript`（唯一剩下的 `chown -R` 提权脚本，
只有一处测试引用它），需要修所有权时改为把应用挪回本地再操作。应用入口交换仍然只有
EACCES/EPERM 之后的一次性授权，**不**接常驻助手——它要求的是在 `/Applications` 里做
`RENAME_SWAP` 并清理原副本，能力比挂载大一个量级。`DiskUtility.run` 本来就是先试普通权限、
被 `kDAReturnNotPrivileged` 拒绝才提权，这条结构保留。

**常驻助手。** 四个文件分担四件事：

- `PrivilegedHelperProtocol.swift`：身份常量（`com.shimoko.AppPorts.privileged-helper`）、
  `@objc` XPC 协议，以及命令白名单 `PrivilegedMountCommand`。
- `PrivilegedHelperService.swift`：以 root 运行的 `NSXPCListener`（`dispatchMain()` 常驻），
  校验调用方、执行白名单命令。
- `PrivilegedHelperInstaller.swift`：把 plist 装进 `/Library/LaunchDaemons` 并 `bootstrap` 到
  system 域，整段是一个 `do shell script`，因此只弹一次密码。
- `PrivilegedHelperClient.swift`：应用侧客户端，握手 + 同步等待回复，最长 60 秒。

**白名单按「命令 + 词法形状」两层判定**：可执行文件只能是 `/usr/sbin/diskutil`、
`/sbin/mount`、`/sbin/umount`；`diskutil` 只放行 `mount`/`unmount`/`mountDisk`/`unmountDisk`/`info`；
`mount` 只接受带 `-u` 的原地重挂；`umount` 只接受一个绝对路径；每个参数必须是绝对路径或已知标志，
拒绝 `..`、`//`、控制字符和超长参数。助手用 `Process` 直接执行，不经过 shell，所以
`sh -c <脚本>` 这类命令**永远进不来**——`guardedCandidateMutationScript`、`apfs deleteVolume`
这些仍走一次性授权。

**调用方校验**（`PeerTrust`）：用 `SecCodeCopyGuestWithAttributes` 按 pid 取对端 `SecCode`，
先 `SecCodeCheckValidity` 确认签名有效；带 Team ID 的正式构建用
`SecRequirement`（同 bundle id + 同 Team ID）放行，本地开发构建没有 Team ID，退化为
「cdhash 与自身镜像完全一致」。握手再比对协议版本与自身 cdhash，应用更新后镜像变了会明确
报「仍是旧镜像」，由设置页提示重装，而不是悄悄失败。

**安装位置**：只允许从 `/Applications` 安装。守护进程以 root 执行磁盘上的可执行文件，
若允许外置卷或用户可写目录，等于把 root 交给那个目录的写权限。

**回退**：任何一步不成立——没装、被拒、镜像过期、超时——`DiskUtility.runPrivileged` 都回到
原来会弹密码的通路。助手只是「少弹密码」的优化，不是唯一通路。

**日志**：助手不接 `AppLogger.shared`。那个单例会读 `UserDefaults`、按当前用户定位日志目录，
在 root 守护进程里既写不到用户能看的位置，也让特权进程多做一堆无关的事。助手的日志只写标准
错误，由 launchd 收进统一日志（`log show --predicate 'process == "AppPorts"'`）。这是对本仓库
「日志统一走 AppLogger」的唯一有意的例外。

## Related decisions

- 与[root 所有的应用只授权位置交换和已验证旧副本清理](../bug-fix/2026-10-20-root应用迁移授权.md)互为补充：
  那篇明确「不安装特权服务」，指的是应用入口交换；本篇只为挂载类命令引入常驻服务，应用交换仍是它
  定义的一次性受限入口，两篇的授权边界都不因此扩大。
- 与[容器卷改为挂载事件驱动](../bug-fix/2026-09-23-event-driven-container-remount.md)部分重叠：
  重挂的触发方式不变，只是执行时多数情况下不再弹密码框。
- 与[APFS 卷创建与所有权](../architecture/2026-10-01-apfs-owners-volume-creation.md)部分重叠：
  卷的创建、删除仍在白名单之外，继续走一次性授权。
- 与[写入登记清理与挂载代理重启](../bug-fix/2026-10-23-写入登记清理与挂载代理重启.md)无关：
  那篇改的是代理的触发方式与授权复用窗口，不改变谁能执行什么命令。

## Alternatives considered

- **延长 `do shell script` 的授权**：最省事，但 AuthServices 的凭据不可导出、不可写盘，
  `NSAppleScript` 复用已经是这条通路的极限（本次只把复用窗口从 120 秒对齐到系统的 300 秒空闲时限）。
  做不到「永久」。
- **`SMAppService` / `SMJobBless` 注册 helper**：这是 Apple 推荐的现代做法，但要求应用有稳定的
  Developer ID 签名与 Team ID；本机 `security find-identity` 为 0 个有效身份，连本地验证都跑不起来。
  另外它同样要弹一次批准，收益与手装 LaunchDaemon 相同，却把「能不能用」绑在签名上。
  最终采用手装 LaunchDaemon，同时保留 `SecRequirement` 校验路径：正式构建下会自动走更严格的判定。
- **setuid 辅助可执行文件**：省掉守护进程与 XPC，但任何能写该文件的用户都等于拿到 root，
  且 macOS 对 setuid 的约束（TCC、签名）会让它更难维护。否决。
- **把 `--privileged-app-transfer` 也接到助手**：调用点会少一次密码框，但等于让常驻 root 服务
  拥有「在 `/Applications` 任意交换目录名并递归删除」的能力，与白名单思路相反。否决。
- **助手接受任意 `diskutil` 子命令**：实现最短，但 `eraseVolume`、`deleteVolume` 一并获得 root，
  一次参数拼错就是数据丢失。否决。

## Consequences

装好之后，挂载与卸载容器卷不再弹密码；卷的创建、删除、签名修复和应用入口交换仍会弹，因为它们
不在白名单里。未安装时行为与改动前完全一致，因此这次改动不会让现有用户更差。

代价与约束：

- 应用每次更新后 cdhash 变化，需要重装一次助手；设置页会把状态显示为「需要重装」，握手会明确
  说明是旧镜像。这是「签名一致的助手」必然的成本，选择接受。
- 助手以 root 运行 `/Applications/AppPorts.app` 里的二进制。应用被移到外盘后无法再安装助手
  （安装器直接拒绝），已装的助手会因镜像不匹配而拒绝工作，两者都落到「弹密码」。
- daemon 的进程生命周期由 launchd 管理，`KeepAlive {SuccessfulExit: false}` 意味着助手崩溃会被拉起；
  正常退出不会。
- 白名单是安全边界，改动它等于改动攻击面，必须同时改 `PrivilegedMountCommandTests`。

## Verification

本机只有 Command Line Tools，没有 Xcode，`security find-identity -v -p codesigning` 报告 0 个有效
身份，因此**没有**执行 `xcodebuild clean build`，也**没有**运行测试套件；这对本仓库的「完成前必须
构建通过」是已知缺口，需要在装有 Xcode 的环境补做。

已完成的检查：

- `swiftc -typecheck` 覆盖 97 个既有非视图文件 + 4 个新增助手文件，除「视图文件未参与导致的
  `DiagnosticExportDialog` 不在作用域」外无错误；`swiftc -parse` 覆盖改动的视图文件。
- 新增 `PrivilegedMountCommandTests`：允许的挂载/卸载/重挂、拒绝破坏性子命令、拒绝 `sh -c`、
  拒绝相对路径与 `..`、拒绝不带 `-u` 的 `mount`、拒绝注入与超长参数、拒绝非法 `-o` 取值。
- 新增 14 条文案的 22 语言译文，按 `LocalizationAuditTests` 的规则自查：语言齐全、占位符一致、
  拉丁语系无汉字、非中文不与源文案相同。

尚未验证、必须补的：真实安装与握手（弹一次密码后挂载不再弹）、应用更新后「需要重装」的提示、
助手拒绝外来调用（另起一个未签名副本尝试连接）、以及白名单之外命令的回退是否仍然弹密码。
