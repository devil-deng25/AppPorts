# Agent Note: 用选项收集问题反馈环境并降低附件门槛

Status: implemented

## Problem

问题反馈要求用户自由输入环境、提供复现步骤，并强制确认诊断包或解释缺失原因。偶发问题和不熟悉系统信息的用户容易被这些要求阻挡，维护者也难以按操作和存储条件归类。

## Decision

问题描述把操作、预期与实际结果放在一起。操作类型、AppPorts 版本、macOS、芯片、存储类型、文件系统和加密状态使用下拉选项；保留原有 app_version、os_version、external_storage_type 字段 ID。所有下拉提供不清楚，存储字段额外提供不适用或未使用外置存储，不预选真实环境。仅问题描述、操作、AppPorts 版本和 macOS 必填。

Build 号单独选填，取消外置设备产品名及型号字段；其他版本和系统小版本可在统一选填补充栏填写。复现步骤、截图、诊断包均选填，诊断导出指引与个人信息检查放在对应附件说明中。保留中英提示，说明只需使用一种语言。不改功能建议或讨论入口。GitHub 原生表单承担渲染，不引入自建表单或新依赖。

## Existing-note audit

检索活跃笔记的反馈流程、问题模板、Issue 模板与 issue template，没有相同决定。其他 Issue 命中是具体故障事实，与反馈收集契约无关，不迁移或归档。

## Alternatives considered

- 保留自由输入环境：可以精确填写任何小版本，但输入负担较高且难统一归类；采用主要版本和环境选项，加一个补充栏。
- 强制附件或缺失理由：能让维护者更早取得诊断，但无法导出时会阻断首次反馈；附件选填，保留清楚的导出入口。

## Verification

Ruby YAML 解析和临时结构断言通过：13 个输入字段、7 个下拉字段，字段 ID 唯一，选项非空、不重复且没有默认环境；仅问题、操作、AppPorts 版本和 macOS 必填。Build、复现步骤及附件均选填，没有设备产品名或强制诊断确认。已按 GitHub 官方表单 schema 核对字段结构；不创建测试 Issue。应用源码未修改，不重跑 Xcode 构建。

## Consequences

选项和具体描述提示减少自由输入负担，缺少附件也能先反馈。固定版本列表需随发布维护。下拉无法穷尽环境，补充栏承接精确版本；没有诊断包的反馈可能需要后续追问。
