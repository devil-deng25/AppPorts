# Agent Note: 主动弹出后的恢复只由设备重连接触发

Status: implemented

## Problem

用户在所有卷已卸载、设备仍连接的菜单中看到“取消弹出并恢复挂载”。该入口要求用户理解 Finder 异步弹出与 AppPorts 暂停的区别，恢复确认又无法证明原生弹出请求已结束。用户要求去掉手动恢复并明确提示重插设备。

## Decision

弹出暂停仅在已保存卷 UUID 出现在新物理连接时解除。菜单保留初次弹出、仍有挂载时的重试和观察状态，删除手动恢复按钮、确认框及 controller/service/store 的显式恢复方法。所有卷已卸载时提示拔下后重新插入；离线提示重新插入，暂停错误和帮助文本指向重连接。

这是对[主动弹出功能](../feature/2026-10-23-explicit-disk-ejection.md)中显式取消暂停决定的部分取代，原篇保留旧选择的理由，其余物理连接识别、暂停准入、独立观察和 Finder 派发继续适用。暂停文档 schema 保持 1，已有暂停按同一重连接规则处理。

本功能文案现已[补齐全部 22 语言](../testing/2026-10-23-本地化覆盖与英文占位守卫.md)，定向英文回退已移除；删除此功能已无引用的恢复文案。安装使用原开发签名并递增产品 build，遵守[签名与授权验收](../bug-fix/2026-10-12-wechat-mount-recovery.md)。

## Existing-note audit

- 主动弹出笔记部分重叠，双方互链；只取代手动恢复路径，不归档整体功能。
- 微信挂载恢复事故和事件重挂笔记仍负责权限及落点验证，不改变这些恢复前置条件。

## Alternatives considered

- 保留确认后的手动恢复：设备不必物理重插就能取消暂停，但原生异步弹出尚未结束时仍可能与重新挂载交错，且用户明确要求移除。
- 在查询到全部卸载后自动恢复：省去用户操作，但会立即重新挂上用户刚要求卸载的卷，与主动弹出的目的冲突。

## Consequences

恢复步骤只剩重新连接设备，产品不再提供绕过物理重连接的取消暂停入口。代价是用户取消 Finder 弹出后如需恢复自动挂载，也要重新连接设备；查询失败保留暂停，不能靠超时解除。若未来能以公开接口可靠终结或确认原生弹出请求，再重新评估免拔插恢复。
