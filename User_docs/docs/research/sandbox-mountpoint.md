# 挂载迁移与系统授权

将外部数据卷接到容器中的原目录，能让一些应用继续使用数据，但不会取消系统权限检查。本次实验中，微信、Maccy 和小米互联服务能够读写；便签仍被拒绝。

## 实验条件 {#environment}

实验于 2026 年 9 月 18 日进行，系统为 macOS 27.0（26A428）、Apple Silicon，外部存储为 APFS。应用包括系统便签、微信 4.1.15、Maccy 和 App Store 版小米互联服务。原记录未完整保存后两者的版本号，因此不能把结果推广到它们的所有版本。

测试保持应用原有签名，没有执行重签名。挂载进程的权限与各个应用自身的权限分别观察。

## 怎样验证 {#method}

1. 备份应用实际使用的子目录，将数据复制到独立的测试卷。
2. 将该卷挂载到原目录，检查真实挂载位置，而非只看命令是否成功。
3. 启动原应用，观察授权提示、原内容、实际读写和系统日志。
4. 比较已授权的执行环境与脚本型后台任务发起挂载的结果，并观察卷未挂载时的表现。

## 观察结果 {#results}

| 场景 | 结果 |
| --- | --- |
| 便签，包含换卷复测 | 能启动，但没有授权弹窗，原内容不可见，读写被系统策略拒绝。 |
| 微信 | 先记录到需要授权，随后获准；原有聊天内容可见，收发可用。 |
| Maccy | 观察到一次预检查拒绝，但实际访问未被阻止，数据库读写可用。 |
| 小米互联服务 | 出现可移动宗卷授权提示，允许后正常读写。 |
| 脚本型后台任务发起挂载 | 容器路径访问权限不足，挂载被拒绝。 |
| 数据卷未挂上，原位置为空目录 | 应用可能向本地空目录写入新数据。 |
| 未挂载位置设置为不可写 | 写入被阻止，但应用仍可能仅显示空白，未明确报错。 |

## 两种权限分别管什么 {#permissions}

**AppPorts 的完全磁盘访问**用于管理受保护目录；**原应用的可移动宗卷权限**用于读写外盘上的数据。前者通过，不代表后者也通过。后台任务也不能仅凭管理员身份取代所需授权。

结果支持“挂载后仍需核对应用实际访问”，不能概括成“系统只比较路径字符串”或“挂载绕过所有检查”。普通用户应通过[准备情况](/docs/settings#permissions)处理授权，再检查原应用内容。

## 结论的范围 {#limits}

这是有限应用与目录的历史验证，不是所有沙盒应用的兼容性保证。便签的失败不能推成所有系统应用都会失败，第三方样本成功也不能保证其他目录适用。

重启后的自动接回另见[重启与外置盘自动接回](/docs/research/prelogin-mount)。旧实验中的系统挂载配置方法保留在[历史方案归档](/docs/archive/mount-experiments)，不作为当前操作步骤。
