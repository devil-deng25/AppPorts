# 为什么有些容器目录不能搬

容器里的目录不全是普通文件夹。2026 年 10 月的企业微信实验中，将特定临时目录挂到外部卷后，文件复制和挂载都成功，但应用启动失败；四个业务数据目录的受测组合则能够启动。

## 实验条件 {#environment}

实验于 2026 年 10 月 1 日进行，系统为 macOS 27.0（26A428）、Apple Silicon。真实应用为企业微信 5.0.11（99998），保留官方签名，使用 USB 连接的 APFS 外部存储。

实验直接使用底层卷与挂载操作，没有通过 AppPorts 界面完成整套迁移。[公开问题 #65](https://github.com/wzh4869/AppPorts/issues/65) 是相关背景，其系统为 27.0.1（26A434），与本实验环境不同。

## 怎样验证 {#method}

1. 将企业微信真实的 `Data/tmp` 数据放入外部卷，挂到原路径后启动应用。
2. 另在隔离目录中直接调用系统检查（不启动完整应用），比较本地目录、外置临时目录、临时目录符号链接和普通业务子目录。
3. 对有真实数据的 `cefcache`、`Profiles`、`WXWork`、`WebKit` 四个目录，每次选择其中一个或多个目录，测试全部 15 种组合。
4. 各组合观察主进程至少 30 秒，检查基本界面、挂载文件可访问性、卷身份与新增崩溃记录。

## 观察结果 {#results}

| 场景 | 结果 |
| --- | --- |
| 真实企业微信：`Data/tmp` 外置挂载 | 启动失败，系统指出临时目录位于不同文件系统设备，随后触发崩溃。 |
| 隔离探针：本地结构 | 通过。 |
| 隔离探针：临时目录外置或变成符号链接 | 失败。 |
| 隔离探针：普通业务后代目录挂载 | 通过。 |
| 四个业务目录的 15 种组合 | 启动与基本界面检查通过，观察期间无新增崩溃。 |
| `UpgradeBeta`、`Wedoc`、`AIModel` | 没有真实数据，未测试。 |

报错中的“不同设备”指文件系统的设备身份，不是硬盘品牌或接口。隔离检查使用了微信和企业微信的身份条件；真实应用启动只测试了企业微信，没有验证微信移动临时目录后的启动结果。

## 对使用有什么意义 {#meaning}

系统会检查容器结构，不能只凭“复制完成”“挂载成功”决定一个目录可迁移。AppPorts 对容器根目录、`Data` 和特定结构节点设有保护，对微信另有允许范围。不要为了移动更大的一层目录而绕过提示。

可以优先查看列表中允许操作的业务子目录，按[迁移数据](/docs/datamigrae/operation)完成检查。

## 结论的范围 {#limits}

15 种组合并未每次恢复到相同快照，也没有覆盖任意操作顺序、长期读写、拔盘或重启。通过基本启动不代表完整功能、所有版本或其他应用都兼容。临时目录的特定失败也不能推成所有名字叫 `tmp` 的目录都相同。
