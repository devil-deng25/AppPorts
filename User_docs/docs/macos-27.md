# macOS 27 升级与修复

如果你曾用旧方式迁移容器数据，或曾同意替换应用签名，建议在升级 macOS 27 前先更新并打开 AppPorts，检查已有迁移。新版提供相应的检查和恢复改进，但**更新 AppPorts 不会自动修好旧签名，也不会自动转换旧迁移**。

原因是旧数据入口、应用身份和系统授权可能不再匹配。我们不要求所有用户升级 macOS 27；本页帮助你在计划升级或已经遇到问题时处理现有应用。详细原因见[macOS 27 与迁移方式的变化](/docs/principles/macos-27)。

## 先判断自己的情况 {#check}

| 你看到的情况 | 下一步 |
| --- | --- |
| 尚未升级系统，曾用经典方式迁移容器或重签应用 | 连接外置盘，检查相关应用；需要修复时先完成下面的步骤。 |
| 已升级，应用打不开且显示“签名已替换” | 退出应用，保留原数据，打开修复说明。 |
| 显示“签名待检查” | 先连接外置盘并重试检查，不要直接重新签名。 |
| 应用正常，数据也可读写 | 无需仅因系统版本就重新迁移；保持备份并正常使用。 |

没有异常徽章也不等于已经验证所有应用的兼容性。若签名检查正常但应用仍打不开，继续[一般问题排查](/docs/faq#launch)。

## 按顺序修复 {#repair}

在应用列表中点击“签名已替换”徽章或“修复”，也可以使用右键菜单的“查看修复步骤”。开始前连接原外置盘，完全退出关联应用，并保留已有副本。

从 1.9.1 build 31 起，新保存的官方原包位于外盘根目录的 `AppPorts Backups`。即使应用仍在内盘，恢复也需要连接保存原包的外盘；有多块盘时，不一定与当前应用库在同一块盘上。先连接原盘再重试，不能把暂时离线当成备份丢失。位置与清理规则见[签名原包](/docs/settings#signature-backups)。

1. **处理旧容器链接。** 若相关容器数据通过旧符号链接迁移，先使用“还原”回到本机。已经使用 APFS 挂载的数据不必仅为签名修复而全部迁回；按修复面板检查的依赖处理。
2. **恢复官方应用身份。** 有可用原包时使用“恢复原始签名”；没有可用材料时，按提示选择匹配的官方原件或从官方渠道重装。若选择官方覆盖安装，应用本体在外盘时先用 AppPorts“迁回本地”；使用可用备份或同版本官方原件修复时无需迁回。不要用会连同个人数据一起清理的卸载方式。
3. **重新检查。** 从 Finder 或 Dock 打开应用，确认原有内容和正常保存都可用。只在终端中启动成功不能替代这个检查。
4. **按需重新迁移数据。** 应用恢复正常后，需要外置存放时再使用符合条件的挂载迁移。

某一步遇到错误时停止继续，保留现有数据和提示中的路径。恢复签名不是再次重签，反复重签不能找回原开发者身份。

## 更新后还要留意什么 {#after}

较早版本可能装过登录时重签的任务。更新后打开一次 AppPorts，让它关闭、移除旧任务；若设置页提示清理未完成，使用“重试”。当前 2.0.0 在所有 macOS 上停用后台自动重签，build 31 已移除常驻开关，正常情况下不会看到这张设置卡。容器数据的[后台接回](/docs/settings#mount-agent)仍然保留。

恢复应用后可能需要重新建立部分系统授权。外盘仍需在使用前连接，适用的首次访问授权仍由 macOS 提示。

## 数据是否已经损坏 {#data}

“签名已替换”首先说明应用身份发生变化，不能仅凭它判断聊天记录或文件损坏。请保留容器目录、外置数据和已有备份，在恢复访问后再核对内容。
