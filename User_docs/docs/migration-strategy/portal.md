# 应用迁移方式

应用搬到外置盘后，AppPorts 会为它保留合适的本地入口。真正占空间的应用与点击时使用的入口，可能不在同一个位置。

## 真实应用与本地入口 {#portal}

普通应用默认使用轻量的**启动壳**，也叫 Stub Portal。你点击本地入口，入口再启动外置盘上的真实应用。它不是第二份完整应用，也不是备份；外置盘不在线时，入口本身不能代替真实应用运行。

```mermaid
flowchart LR
  A[点击本地应用入口] --> B[找到外置盘上的真实应用]
  B --> C[启动应用]
  C --> D[按原有位置访问应用数据]
```

最后一步解释了为什么“迁移应用”和“迁移数据”分开：应用本体移走后，聊天记录和其他数据可能仍在本机。

## 不同内容怎样保留入口 {#types}

| 内容 | AppPorts 的处理方式 |
| --- | --- |
| 普通 macOS 应用 | 使用启动壳指向外部真实应用。 |
| 支持迁移的 iPhone／iPad 应用 | 使用适合其包装结构的启动入口；能否迁移仍受系统和应用条件限制。 |
| 包含多个应用的文件夹或套件 | 使用文件夹镜像，为其中应用建立入口，其余受管内容通过链接关联。 |
| 手动选择传统链接迁移 | 右键“使用传统链接迁移”，将整个应用放在外部，本地保留符号链接。它仍是可用的手动选项，兼容性取决于应用。 |
| 历史迁移项目 | 识别旧入口，提供相应的还原或解除操作。 |

旧版的整体符号链接、Contents 目录入口可能仍出现在已有迁移中。“仍能识别”不代表当前新迁移默认使用它们。目录结构或应用内部路径的特殊依赖，也可能影响兼容性。

## 为什么有更新保护 {#updates}

有些自更新程序会替换或删除正在更新的应用。对需要保护的应用，AppPorts 会提供锁定迁移，降低外部副本被更新流程意外改动的风险。

锁定也可能阻止应用自行更新。遇到更新失败时，应按 AppPorts 的提示处理，或迁回本地更新后再迁出；不要反复手工删除不认识的文件。

“Sparkle”“Electron”说明应用使用的框架或更新线索，不单独等于“必须锁定”或“一定无法更新”。具体操作见[迁移应用后的更新](/docs/core#updates)。

## 这对你意味着什么 {#limits}

本地入口尽量保留熟悉的打开方式，但它不能消除外盘依赖，也不能保证所有插件、系统权限和应用自身更新都不受影响。迁移完成后，应从平时使用的入口启动，并检查常用功能。
