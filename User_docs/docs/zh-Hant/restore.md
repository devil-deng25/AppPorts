# 還原、接回與解除連結

先確認你想改變的是**存放位置**還是**訪問入口**。開始前連線原來的外接磁碟，儲存工作並退出相關應用；還原到本機還需要足夠的本地空間。

## 選擇正確的操作 {#choose}

| 目的 | 操作 | 完成後的資料位置 |
| --- | --- | --- |
| 把應用從外接磁碟搬回 Mac | 遷移回本地 | 真實應用回到本機。 |
| 把已遷移的資料搬回原目錄 | 還原 | 資料回到本機原位置。 |
| 應用在外接磁碟，只缺啟動入口 | 連結回本地 | 真實應用仍在外接磁碟。 |
| 資料在外接磁碟，本地連結丟了 | 接回 | 資料仍在外接磁碟，重建本地訪問入口。 |
| 資料卷線上但未接到原目錄 | 掛載 | 資料仍在外接磁碟，恢復原路徑的訪問。 |
| 只移除應用的本地入口 | 本地列表的垃圾桶按鈕 | 外接磁碟上的真實應用保留。 |

## 把應用遷回本地 {#apps}

1. 在外部應用庫選中應用，點選“遷移回本地”。
2. 核對本地目標。若存在同名真實應用或其他衝突，先處理提示，不要自行覆蓋。
3. 等待複製、檢查和收尾完成。
4. 從 Finder 或 Dock 開啟應用，檢查它現在使用的本地副本。

遷回應用本體不會自動遷回另行管理的資料。需要一起恢復時，繼續處理下面的資料目錄。

## 把資料還原到原位置 {#data}

1. 在資料目錄或目錄遷移中找到受管專案，點選“還原”。
2. 確認應用已退出、原外接磁碟線上、本機空間足夠。
3. 等待 AppPorts 將資料複製回原位置並完成切換。
4. 開啟應用檢查內容和儲存功能，確認最終狀態。

還原完成後，AppPorts 會處理可安全清理的外部副本或專用卷。若提示仍有保留內容或未完成清理，先保留它們並按提示繼續；不要把“能開啟應用”當成全部收尾已經完成。

## 只恢復入口 {#reconnect}

應用顯示“未連結”或只有外部副本時，選中後使用“連結回本地”。資料顯示“待接回”時，核對外部目標後使用“接回”；“待掛載”的容器卷則使用“掛載”。

這些操作不把資料搬回內建盤。若本地原位置已經產生新內容，先確認兩份資料的用途，不能用覆蓋來強行恢復入口。

## 解除應用連結 {#unlink}

在本地應用列表中，找到已連結應用並點選行末垃圾桶按鈕，懸停提示為“斷開此連結並刪除檔案”；孤立連結也可右鍵選擇“刪除孤立連結”。這會移除 AppPorts 管理的本地入口，外接磁碟上的真實應用保留。**它不是資料目錄的還原操作。** 之後仍可重新“連結回本地”。

刪除 AppPorts 前，先還原仍由它管理的容器資料；否則自動掛載任務可能失去所需程式。中斷、離線或目標衝突的處理見[常見問題與排查](/docs/faq)。

## 處理未完成操作與保留副本 {#recovery}

在「任務中心」開啟需要處理的任務，點擊「處理異常」，先看目前遷移記錄。結束關聯應用，接好並解鎖原磁碟；權限不足時使用「檢查權限」，再重試。重試範圍以面板列出的項目為準，重試待處理操作可能涉及多筆記錄。

| 資料異常面板中的選擇 | 實際作用 |
| --- | --- |
| 重試／重新嘗試清理 | 重新檢查並繼續相應操作；不會強制刪除有差異的舊檔案。 |
| 稍後處理 | 暫停自動處理，保留檔案，之後可以主動重試。 |
| 打開舊副本 | 在資料已切換、位置核對通過時查看保留內容。 |
| 保留副本並結束清理 | 僅在資料已切換後提供；停止自動清理和異常提醒，舊副本仍佔空間，可再開啟或單獨重試清理。 |

主體遷移完成但舊副本尚未清理時，任務仍可能顯示「需要處理」。背景完成了舊現場清理，也不能據此把原遷移判為成功；請結合目錄實際狀態核對。移除任務歷史不會解決這些記錄。

應用異常面板另有「重試處理」「忽略錯誤結束任務」和「忽略錯誤強制回遷」。優先重試正常處理。「忽略錯誤結束任務」只把原記錄歸檔為未完成並保留檔案；**「忽略錯誤強制回遷」不進行內容驗證**，會在複製成功後替換本機入口，保留外接磁碟原件及已有本機副本，原記錄仍歸檔為未完成。只有理解確認框含義並願意自行檢查結果時才使用，不能視為正常還原成功。
