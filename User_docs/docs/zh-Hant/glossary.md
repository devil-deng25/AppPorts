# 名詞解釋

這裡解釋 AppPorts 介面與文件中的常用說法。前半部分是產品中的操作和狀態，後半部分是 macOS 與檔案系統的通用概念；看到具體徽章時，可查[徽章與狀態](/docs/badges)。

## AppPorts 中的位置與入口 {#locations}

### 本地入口、啟動殼、殼門（Stub Portal） {#local-portal}

遷移後留在 Mac 上、負責開啟外部真實應用的小入口。它不是完整應用，也不是備份；外接磁碟不線上時不能憑這個入口執行完整程式。見[應用遷移方式](/docs/migration-strategy/portal#portal)。

### 真實應用、外部副本 {#real-app}

包含完整程式的應用本體，與本地啟動殼相對。“外部副本”在遷移完成後可能是唯一正在使用的真實應用，不能僅因名稱有“副本”就刪除。

### 資料夾鏡像（Folder Mirror） {#folder-mirror}

為應用套件保留本地目錄結構，內部入口連線到外部的應用或檔案。這裡的“映象”不是磁碟映像，也不是另一套完整備份。見[套件目錄](/docs/migration-strategy/portal#types)。

## 遷移與恢復操作 {#operations}

### 應用遷移 {#app-migration}

移動應用本體並管理本地啟動入口。應用的聊天記錄、快取和專案未必隨它一起移動，詳見[遷移應用](/docs/core)。

### 資料遷移 {#data-migration}

移動應用資料、工具目錄或自選資料夾。可以在不移動應用本體的情況下單獨使用，詳見[遷移資料](/docs/datamigrae/operation)。

### 連結遷移 {#linked-migration}

資料放到外部位置，原目錄變成指向它的符號連結。應用訪問原路徑時被引導到目標位置；權限限制仍然有效。

### 掛載遷移 {#mount-migration}

把適用的容器資料放入專用 APFS 資料卷，再將卷接到原目錄。它保留真實應用簽名，當前需要APFS 儲存。見[資料遷移方式](/docs/datamigrae/baseinfo#mount)。

### 遷回、還原 {#restore}

把外部應用或資料搬回本機。“遷移回本地”用於應用，“還原”常用於資料目錄；都不同於只恢復入口的接回。見[還原步驟](/docs/restore)。

### 接回、掛載 {#reconnect}

恢復原位置對外部資料的訪問，資料仍留在外接磁碟。“接回”常指重建連結，“掛載”是將資料卷接到原目錄，不會把資料複製回內建盤。

### 解除連結 {#unlink}

移除 AppPorts 管理的應用本地入口，外部真實應用保留。它不等同於刪除外部應用，也不等同於還原資料目錄。

### 整理 {#normalize}

將可識別的受管目錄或現有連結調整到 AppPorts 使用的規範位置。執行前要核對真實目標；當前預設模式不會藉此重新建立舊式容器連結。

## 模式與保護 {#modes}

### 經典資料遷移模式 {#classic-mode}

為舊式容器連結遷移保留的相容模式，預設關閉。它仍受目錄保護與風險確認約束，當前不再包含自動重簽流程。見[經典模式](/docs/classic-mode)。

### 鎖定遷移、更新保護 {#update-protection}

限制部分應用更新器改動外部真實應用，以避免更新破壞遷移結果。它不是磁碟加密，也不能防止硬碟故障。見[更新保護](/docs/migration-strategy/portal#updates)。

### 待遷出 {#pending-move}

檢測到本地真實應用比外部副本更新時顯示的狀態。核對版本後，可以再次遷移本地新版；並不表示遷移正在背景執行。

### 歷史功能歸檔 {#archive}

儲存停用功能、舊版做法和未採用實驗方案的說明，並標明版本與當前替代方式。它們不屬於當前操作指南。見[歷史功能歸檔](/docs/archive/overview)。

### 簽名原包、AppPorts Backups {#signature-backup}

手動重簽前儲存的完整官方應用，用於恢復應用內容與原始簽名。1.9.1 build 31 起，它自動儲存在合適外接磁碟根目錄的 `AppPorts Backups` 資料夾，內附 `README.txt`；恢復時需要連線該盤。它不包含聊天記錄、文件等個人資料，刪除後會失去這份離線恢復材料。見[原包儲存與清理](/docs/settings#signature-backups)。

## 系統與檔案的通用概念 {#system}

### 符號連結、軟連結 {#symlink}

記錄另一個檔案或目錄位置的特殊檔案，類似一張指路紙條。目標移走或離線時，紙條仍可能存在；它不會替使用者增加訪問權限。

### 沙盒 {#sandbox}

系統對應用訪問範圍的限制。應用即使知道某個檔案在哪裡，也可能沒有權限開啟；AppPorts 無法用一個連結替應用取消這些限制。

### 應用容器、容器資料 {#app-container}

macOS 為應用及應用組管理的資料區域，常見位置名稱為 `Containers` 與 `Group Containers`。它們與磁碟上的 APFS 容器不是同一概念。

### APFS 容器與卷 {#apfs}

APFS 是 Apple 的檔案系統。一個 APFS 容器可以包含多個共享儲存空間的卷；AppPorts 的掛載遷移會建立專用資料卷，不是把應用本身裝進另一個程式。

### 掛載點 {#mountpoint}

一個卷在檔案系統中出現的位置。將外部資料卷掛到應用原目錄後，訪問該目錄就會訪問卷裡的內容；仍需要滿足系統權限。

### 開發者簽名、重簽名 {#signing}

開發者簽名幫助系統核對應用來源和完整性。AppPorts 所說的本地重簽（Ad-hoc）會替換籤名，不能冒充原開發者，還可能改變應用的授權行為。

### 恢復原始簽名 {#original-signature}

使用經過檢查的官方原始應用檔案，恢復原有簽名與相關內容，不是再次做本地重簽。僅有舊身份名稱的記錄不足以恢復；需要有效原始副本或適用的官方原版。見[升級與修復](/docs/macos-27#repair)。
