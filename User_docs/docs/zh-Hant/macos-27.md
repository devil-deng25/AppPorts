# macOS 27 升級與修復

如果你曾用舊方式遷移容器資料，或曾同意替換應用簽名，建議在升級 macOS 27 前先更新並開啟 AppPorts，檢查已有遷移。新版提供相應的檢查和恢復改進，但**更新 AppPorts 不會自動修好舊簽名，也不會自動轉換舊遷移**。

原因是舊資料入口、應用身份和系統授權可能不再匹配。我們不要求所有使用者升級 macOS 27；本頁幫助你在計劃升級或已經遇到問題時處理現有應用。詳細原因見[macOS 27 與遷移方式的變化](/docs/principles/macos-27)。

## 先判斷自己的情況 {#check}

| 你看到的情況 | 下一步 |
| --- | --- |
| 尚未升級系統，曾用經典方式遷移容器或重簽應用 | 連線外接磁碟，檢查相關應用；需要修復時先完成下面的步驟。 |
| 已升級，應用打不開且顯示“簽名已替換” | 退出應用，保留原資料，開啟修復說明。 |
| 顯示“簽名待檢查” | 先連線外接磁碟並重試檢查，不要直接重新簽名。 |
| 應用正常，資料也可讀寫 | 無需僅因系統版本就重新遷移；保持備份並正常使用。 |

沒有異常徽章也不等於已經驗證所有應用的相容性。若簽名檢查正常但應用仍打不開，繼續[一般問題排查](/docs/faq#launch)。

## 按順序修復 {#repair}

在應用列表中點選“簽名已替換”徽章或“修復”，也可以使用右鍵選單的“檢視修復步驟”。開始前連線原外接磁碟，完全退出關聯應用，並保留已有副本。

從 1.9.1 build 31 起，新儲存的官方原包位於外接磁碟根目錄的 `AppPorts Backups`。即使應用仍在內建磁碟，恢復也需要連線儲存原包的外接磁碟；有多塊盤時，不一定與當前應用庫在同一塊盤上。先連線原盤再重試，不能把暫時離線當成備份丟失。位置與清理規則見[簽名原包](/docs/settings#signature-backups)。

1. **處理舊容器連結。** 若相關容器資料透過舊符號連結遷移，先使用“還原”回到本機。已經使用 APFS 掛載的資料不必僅為簽名修復而全部遷回；按修復面板檢查的依賴處理。
2. **恢復官方應用身份。** 有可用原包時使用“恢復原始簽名”；沒有可用材料時，按提示選擇匹配的官方原件或從官方渠道重灌。若選擇官方覆蓋安裝，應用本體在外接磁碟時先用 AppPorts“遷回本地”；使用可用備份或同版本官方原件修復時無需遷回。不要用會連同個人資料一起清理的解除安裝方式。
3. **重新檢查。** 從 Finder 或 Dock 開啟應用，確認原有內容和正常儲存都可用。只在終端中啟動成功不能替代這個檢查。
4. **按需重新遷移資料。** 應用恢復正常後，需要外接存放時再使用符合條件的掛載遷移。

某一步遇到錯誤時停止繼續，保留現有資料和提示中的路徑。恢復簽名不是再次重簽，反覆重簽不能找回原開發者身份。

## 更新後還要留意什麼 {#after}

較早版本可能裝過登入時重簽的任務。更新後開啟一次 AppPorts，讓它關閉、移除舊任務；若設定頁提示清理未完成，使用“重試”。當前 1.9.1 開發版在所有 macOS 上停用背景自動重簽，build 31 已移除常駐開關，正常情況下不會看到這張設定卡。容器資料的[背景接回](/docs/settings#mount-agent)仍然保留。

恢復應用後可能需要重新建立部分系統授權。外接磁碟仍需在使用前連線，適用的首次訪問授權仍由 macOS 提示。

## 資料是否已經損壞 {#data}

“簽名已替換”首先說明應用身份發生變化，不能僅憑它判斷聊天記錄或檔案損壞。請保留容器目錄、外接資料和已有備份，在恢復訪問後再核對內容。
