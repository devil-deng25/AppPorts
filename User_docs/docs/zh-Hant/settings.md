# 設定與權限

點選主視窗右上角的齒輪進入設定。遷移前先檢視“準備狀況”，按提示完成所需權限與外接儲存檢查；不同 macOS 版本顯示的專案可能不同。

## 準備狀況與系統權限 {#permissions}

| 專案 | 用途 | 怎樣處理 |
| --- | --- | --- |
| 完全磁碟訪問 | 讓 AppPorts 讀取和管理受保護的資料位置。 | 從準備狀況前往系統設定，授權後按提示重新開啟 AppPorts。 |
| App 管理 | 系統要求時，允許管理其他應用。 | 按系統彈窗或準備狀況中的入口授權。 |
| 可移動宗卷 | 讓遷移後的應用訪問外接磁碟資料。 | 原應用首次訪問時可能單獨詢問；這與 AppPorts 的權限不同。 |
| 外部儲存 | 檢查連線、格式和加密狀態。 | 按[外接磁碟準備](/docs/storage-guide)選擇合適目標。 |

安裝位置和本次所需空間，以選擇目錄並點選遷移後的檢查提示為準。請將 AppPorts 放入“應用程式”後執行，避免直接從安裝映像啟動。

給 AppPorts 授權不代表其他應用也獲得授權。遇到讀不到資料的問題，先檢查[掛載狀態與原應用權限](/docs/faq#missing-data)。

## App Store 與非原生應用 {#app-store}

macOS 15.1 及以上支援 App Store 管理外接安裝，AppPorts 不再要求手動開啟這兩類遷移開關。可在 App Store 設定中檢視大型 App 的外接下載選項。

較早系統會顯示“允許遷移 Mac App Store 應用”和“允許遷移非原生應用”。開啟前閱讀提示：系統支援、應用更新與裝置要求仍然適用。詳見[遷移應用](/docs/core#updates)。

## 經典資料遷移模式 {#classic-data-migration-mode}

“經典資料遷移模式（不推薦）”預設關閉，為仍需處理舊容器連結方式的使用者保留。開啟需要確認風險，關閉不會還原已有資料，也不會恢復被修改的簽名。

當前遷移與重簽名分開進行。這個開關不會恢復舊版自動重簽流程。適用範圍與轉回方法見[經典模式](/docs/classic-mode)，舊版行為儲存在[歷史功能歸檔](/docs/archive/data-signing)。

## 手動簽名與修復 {#manual-signing}

簽名操作處理的是應用身份，不是把檔案搬到另一個位置。只有明確知道用途時才使用手動重簽；沙盒應用預設受限，經典模式下仍需要針對當前操作確認風險。

應用列表確認某個應用已重簽後，右鍵選單保留“恢復原始簽名”，隱藏重複的“重簽名此應用”。恢復官方狀態後，符合條件的應用才重新顯示重簽入口。檢查結果不明時，先使用“檢查簽名”，不能只看選單判斷應用是否正常。

“恢復原始簽名”需要適用且經核對的原始應用備份，不能拿另一個版本強行替換。有“簽名已替換”提示時，從修復面板開始；沒有可用備份時，按指引使用官方原版。完整步驟見[升級與修復](/docs/macos-27#repair)。

### 原包儲存在哪裡 {#signature-backups}

從 1.9.1 build 31 起，手動重簽官方應用時，AppPorts 將經核對的完整原包儲存在**外接磁碟根目錄可見的 `AppPorts Backups` 資料夾**，並放入中英文 `README.txt`。無需額外選擇備份位置，也沒有單獨的備份管理頁面；可以直接在 Finder 中檢視。

AppPorts 會依次嘗試應用所在的外接磁碟、當前外部應用庫所在的盤，再從其他合適的外接磁碟中優先選擇剩餘空間較多的卷。目標必須是已連線、可寫且空間足夠的本地物理外接磁碟；內建磁碟、網路盤和磁碟映像不參與選擇。沒有合適外接磁碟時，在修改正式應用前停止。

**應用仍在內建磁碟，也需要連線外接磁碟儲存原包。** 內建磁碟只長期保留小型索引和操作記錄；重簽期間仍需臨時工作空間。原包在同一卷內可以直接移入備份目錄；需要跨卷時，先複製並確認外接磁碟原包完整儲存，再清理內部臨時原件。

這些原包用於恢復應用內容和官方簽名，**不包含聊天記錄、文件等應用資料**。它們也不替代獨立備份：同一塊外接磁碟故障時，盤上的應用和原包可能同時不可用。

### 恢復與清理原包 {#signature-backup-cleanup}

恢復時連線儲存原包的那塊外接磁碟，在 AppPorts 中對當前應用選擇“恢復原始簽名”。程式會核對版本、內容、開發者身份及相關資料依賴；同一版本即使重複重簽，也仍保留最初的官方原包，不會用重簽後的副本覆蓋它。

AppPorts 會保留仍有恢復價值的原包。在確認應用已經恢復官方狀態，或已安裝經驗證的同開發者官方新版，並排除未完成操作和資料依賴後，才自動清理冗餘原包。舊版留在內建磁碟的有效完整原包會在條件滿足時自動遷到外接磁碟，確認成功後再移除內部副本。

如果確定不再需要這份恢復材料，可以在 Finder 中刪除對應原包。刪除不會移除當前安裝的應用或個人資料，但會失去這份原包提供的離線恢復能力；之後可能需要從官方渠道重灌。移入廢紙簍仍佔空間，APFS 共享資料塊也使顯示大小不等於最終釋放量。

請保持備份資料夾的位置，不要修改原包內容，也不要把它當作日常應用啟動。外接磁碟暫時離線不等於原包失效；尚有操作未完成時，先按 AppPorts 的提示處理。只有身份名稱的舊記錄如何保留或清理，見[歷史簽名備份](/docs/archive/data-signing#backups)。

### 舊登入任務 {#login-signing}

當前版本在所有 macOS 上停用“開機自動重簽名”，build 31 也已移除對應設定卡。更新後開啟一次 AppPorts，讓它處理舊登入任務；僅清理失敗時，設定才顯示“舊的登入重簽任務尚未完全關閉，請重試。”，此時使用“重試”並保留錯誤資訊。

## 背景接回 {#mount-agent}

掛載遷移會配置登入後的接回任務，用於將線上的資料卷接到原目錄。它不替應用重簽名，也不保證在所有登入應用啟動前完成。

移動或更新 AppPorts 後開啟一次，讓它檢查背景程式位置。系統需要管理員授權時，開啟 AppPorts 完成操作。刪除 AppPorts 前先[還原受管容器資料](/docs/restore#data)。

## 日誌設定 {#logs}

可以開關日誌記錄、調整最大日誌大小，在 Finder 中檢視日誌，或清空已有日誌。需要反饋問題時，透過選單欄“日誌 → 匯出診斷包”生成檔案；匯出不會自動傳送。

提交前檢查內容，說明系統版本、AppPorts 版本、發生的操作和介面提示。見[反饋問題](/docs/faq#feedback)與[隱私政策](/docs/privacy)。
