# 迁移数据

数据迁移适合移动应用产生的数据、工具目录或自己的文件夹。它与应用本体迁移相互独立：应用留在本机，也可以迁移适用的数据。

## 先找到要迁移的内容 {#choose}

| 内容 | 从哪里进入 |
| --- | --- |
| 应用的聊天记录、缓存等关联数据 | “数据目录 → 应用数据”，选中应用，再展开目录。 |
| 包管理器缓存、模型等工具数据 | “数据目录 → 工具目录”，查看已识别项目。 |
| 自己的项目、素材或其他文件夹 | “目录迁移”，点击本地文件夹区域的“+”，选择源文件夹和外部目标。 |

应用数据列表默认只显示可迁移、可挂载和需要处理的项目。打开“显示锁定目录结构”，会把可操作项目之上的锁定祖先补回来，用来说明层级；没有可操作内容的锁定目录不会因此出现。要一次看完所有不可迁移目录，打开“显示不支持迁移目录”。是否显示零字节目录由第三个开关控制。**列表提供迁移操作，也不代表执行检查一定通过**：空间、权限、正在使用数据的进程，以及与已有迁移的父子关系仍需核对。

点击“已链接”“挂载迁移”“现有软链”等状态统计，可以只看匹配项目；列表会保留必要的父级路径。各状态数字不会随这一次选择而缩小，但仍受其他搜索与筛选条件影响。再次点击或清除筛选可恢复，切换应用或页签也会重置筛选。

标为“用户目录入口”的桌面、下载、图片等快捷入口，并不是这个应用独占的数据，不统计目标大小，也不提供迁移或还原。大小旁的“本卷大小”“目标大小”说明统计范围；父目录和子行不能简单相加，显示大小也不等于迁移后一定释放的空间。

## 迁移前的准备 {#prepare}

1. 备份重要数据，连接目标外置盘并检查空间。
2. 保存工作，完全退出使用这些数据的应用、工具和后台任务。
3. 在 AppPorts 的“设置 → 准备情况”中检查权限。AppPorts 应从“应用程序”文件夹运行。
4. 核对目录名称和位置，避免仅凭大小猜测它属于哪个应用。

检测到关联应用仍在运行时，AppPorts 可以提供“退出应用并继续”，请求应用正常退出。若应用仍等待保存或退出确认，先处理完它的提示，再回到 AppPorts 点击“继续”。

## 普通目录迁移 {#linked}

对提供“迁移”按钮的普通目录，点击后检查目标位置，再确认开始。AppPorts 会复制并检查数据，随后在原位置建立[符号链接](/docs/glossary#symlink)。完成后通常显示“已链接”。

工具目录的常见例子包括 npm、Gradle 的缓存，以及部分模型和编辑器数据。工具本身的任务也需要退出；正在下载、构建或写入的目录不适合同时移动。

自选文件夹应是用户目录内的真实文件夹，不能是整个用户目录，也不能与已管理的目录相互包含。目标位置会在添加时显示，确认后再迁移。

## 容器数据挂载迁移 {#mount}

默认模式下，适用的容器数据使用“迁移”按钮，检查通过后执行挂载迁移；开启经典模式时，它会单独显示为“挂载迁移”。这需要**APFS 外置存储**、足够空间和正确权限。

1. 默认模式点击“迁移”（经典模式选择“挂载迁移”），阅读存储和权限检查结果。
2. 条件不足时选择其他位置，或保留本地数据；不必为了继续而清空现有磁盘。
3. 加密目标按提示为新数据卷设置密码，选择是否保存到本机钥匙串；详见[加密盘](/docs/storage-guide#encrypted-drives)。
4. 检查本次数据与目标，确认迁移。操作完成后状态应为“已挂载”。
5. 打开原应用；若 macOS 询问是否允许访问可移动宗卷，按你的使用意愿授权。
6. 检查原有内容能否读取，并验证一次正常保存。

挂载迁移不会替换应用签名，但应用仍受系统授权和自身兼容性限制。看不到原数据时应先停止继续写入，按[数据不可见排查](/docs/faq#missing-data)检查。

## 微信账号：全部迁移或拆分迁移 {#wechat}

对识别到的微信账号目录点击迁移后，在“微信账号迁移”中选择：

- “全部迁移”：迁移所选账号的整个目录。
- “拆分迁移”：只迁移媒体文件，数据库和配置保留本地；确认框分别列出媒体大小与本地保留大小。

等目录大小读取完整后，再点击“开始迁移”。切换这两种方式前需要先完整还原，其他微信数据不受本次账号操作影响。拆分后离线时能否继续查看文字消息取决于微信版本，不保证所有内容在未连盘时可用。加密目标还需[设置数据卷密码](/docs/storage-guide#encrypted-drives)。

## 怎样看迁移进度 {#progress}

“总体进度（估算）”包含准备、扫描、复制、磁盘写入、各轮校验、切换和收尾；多个目录会合算为同一任务的总体百分比。当前目录另有“准备 → 扫描 → 复制 → 校验 → 切换 → 收尾”阶段提示。**总体百分比、当前目录阶段与已复制字节表示不同范围，不能互相替代。** 复制达到 100% 不代表任务完成，空间释放也要等清理完成。

扫描和校验会显示已处理项数、读取字节或当前文件。长时间没有新的进展时，窗口会说明距离上次活动的时间；先结合阶段和提示判断，不要只因百分比暂时不变就拔盘或强制退出。

## 完成后与异常情况 {#after}

打开应用前先连接外置盘，并确认数据已接回。显示“待挂载”时按提示挂载；“外置盘未连接”并不等于数据已被删除。其他状态见[徽章与状态](/docs/badges#data)。

需要恢复本机存放或重建入口时，阅读[还原与接回](/docs/restore)。中断或只剩清理未完成时，保留 AppPorts 提示的副本，不要反复创建新的迁移。

相关内容：[两种数据迁移方式](/docs/datamigrae/baseinfo) · [外置盘准备](/docs/storage-guide#apfs) · [经典模式](/docs/classic-mode)

想了解锁定目录和父子层级限制的来由，可阅读[数据目录的迁移边界](/docs/blog/data-migration-boundaries)。

## 在任务中心管理迁移 {#task-center}

点击工具栏“任务中心”查看应用、应用数据、工具目录和目录迁移任务。点击任务名称打开详情；详情中的“加入后台”只收起窗口，任务继续在 AppPorts 内运行，可以切换页面后再回来查看。它不表示退出 AppPorts 后还能继续。

- 选中一个或多个任务，使用“暂停”“继续”或“取消任务”。暂停要等到可暂停的位置；入口切换等关键步骤可能先完成。
- 取消后若显示“正在取消，等待安全收尾”，请保持磁盘连接并等待。取消不会撤销已完成的迁移步骤，也不保证立即释放占用空间。
- 互不冲突的任务可以并行，存在路径或资源冲突的任务会排队；排队不等于卡住。
- “清空已完成”和行末移除按钮只删除任务展示记录，不删除文件，也不处理尚未完成的恢复或清理。

重新打开 AppPorts 后，上次未结束的任务需要先检查迁移记录，不会仅凭任务历史自动重新迁移。出现“需要处理”时打开详情的“处理异常”，按当前记录继续；具体见[异常恢复](/docs/restore#recovery)。

## 迁移期间的启动保护 {#launch-protection}

迁移或迁回应用数据时，经过已更新的 AppPorts 原生 macOS 启动入口打开关联应用，会提示等待完成；复制暂停时也会保持保护，排队尚未执行的任务不会因此阻止启动。

这不能拦截所有启动方式：直接打开外盘真实应用、仍在本机的应用本体、旧入口和 iOS 包装应用均可能绕过。仍须先完全退出应用及后台写入工具，并等待任务和安全收尾结束后再打开。
