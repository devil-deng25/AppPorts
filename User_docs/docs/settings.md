# 设置与权限

点击主窗口右上角的齿轮进入设置。迁移前先查看“准备情况”，按提示完成所需权限与外置存储检查；不同 macOS 版本显示的项目可能不同。

## 准备情况与系统权限 {#permissions}

| 项目 | 用途 | 怎样处理 |
| --- | --- | --- |
| 完全磁盘访问 | 让 AppPorts 读取和管理受保护的数据位置。 | 从准备情况前往系统设置，授权后按提示重新打开 AppPorts。 |
| App 管理 | 系统要求时，允许管理其他应用。 | 按系统弹窗或准备情况中的入口授权。 |
| 可移动宗卷 | 让迁移后的应用访问外盘数据。 | 原应用首次访问时可能单独询问；这与 AppPorts 的权限不同。 |
| 外部存储 | 检查连接、格式和加密状态。 | 按[外置盘准备](/docs/storage-guide)选择合适目标。 |

安装位置和本次所需空间，以选择目录并点击迁移后的检查提示为准。请将 AppPorts 放入“应用程序”后运行，避免直接从安装映像启动。

给 AppPorts 授权不代表其他应用也获得授权。遇到读不到数据的问题，先检查[挂载状态与原应用权限](/docs/faq#missing-data)。

## App Store 与非原生应用 {#app-store}

macOS 15.1 及以上支持 App Store 管理外置安装，AppPorts 不再要求手动打开这两类迁移开关。可在 App Store 设置中查看大型 App 的外置下载选项。

较早系统会显示“允许迁移 Mac App Store 应用”和“允许迁移非原生应用”。开启前阅读提示：系统支持、应用更新与设备要求仍然适用。详见[迁移应用](/docs/core#updates)。

## 经典数据迁移模式 {#classic-data-migration-mode}

“经典数据迁移模式（不推荐）”默认关闭，为仍需处理旧容器链接方式的用户保留。开启需要确认风险，关闭不会还原已有数据，也不会恢复被修改的签名。

当前迁移与重签名分开进行。这个开关不会恢复旧版自动重签流程。适用范围与转回方法见[经典模式](/docs/classic-mode)，旧版行为保存在[历史功能归档](/docs/archive/data-signing)。

## 手动签名与修复 {#manual-signing}

签名操作处理的是应用身份，不是把文件搬到另一个位置。只有明确知道用途时才使用手动重签；沙盒应用默认受限，经典模式下仍需要针对当前操作确认风险。

应用列表确认某个应用已重签后，右键菜单保留“恢复原始签名”，隐藏重复的“重签名此应用”。恢复官方状态后，符合条件的应用才重新显示重签入口。检查结果不明时，先使用“检查签名”，不能只看菜单判断应用是否正常。

“恢复原始签名”需要适用且经核对的原始应用备份，不能拿另一个版本强行替换。有“签名已替换”提示时，从修复面板开始；没有可用备份时，按指引使用官方原版。完整步骤见[升级与修复](/docs/macos-27#repair)。

### 原包保存在哪里 {#signature-backups}

从 1.9.1 build 31 起，手动重签官方应用时，AppPorts 将经核对的完整原包保存在**外盘根目录可见的 `AppPorts Backups` 文件夹**，并放入中英文 `README.txt`。无需额外选择备份位置，也没有单独的备份管理页面；可以直接在 Finder 中查看。

AppPorts 会依次尝试应用所在的外盘、当前外部应用库所在的盘，再从其他合适的外盘中优先选择剩余空间较多的卷。目标必须是已连接、可写且空间足够的本地物理外盘；内盘、网络盘和磁盘映像不参与选择。没有合适外盘时，在修改正式应用前停止。

**应用仍在内盘，也需要连接外盘保存原包。** 内盘只长期保留小型索引和操作记录；重签期间仍需临时工作空间。原包在同一卷内可以直接移入备份目录；需要跨卷时，先复制并确认外盘原包完整保存，再清理内部临时原件。

这些原包用于恢复应用内容和官方签名，**不包含聊天记录、文档等应用数据**。它们也不替代独立备份：同一块外盘故障时，盘上的应用和原包可能同时不可用。

### 恢复与清理原包 {#signature-backup-cleanup}

恢复时连接保存原包的那块外盘，在 AppPorts 中对当前应用选择“恢复原始签名”。程序会核对版本、内容、开发者身份及相关数据依赖；同一版本即使重复重签，也仍保留最初的官方原包，不会用重签后的副本覆盖它。

AppPorts 会保留仍有恢复价值的原包。在确认应用已经恢复官方状态，或已安装经验证的同开发者官方新版，并排除未完成操作和数据依赖后，才自动清理冗余原包。旧版留在内盘的有效完整原包会在条件满足时自动迁到外盘，确认成功后再移除内部副本。

如果确定不再需要这份恢复材料，可以在 Finder 中删除对应原包。删除不会移除当前安装的应用或个人数据，但会失去这份原包提供的离线恢复能力；之后可能需要从官方渠道重装。移入废纸篓仍占空间，APFS 共享数据块也使显示大小不等于最终释放量。

请保持备份文件夹的位置，不要修改原包内容，也不要把它当作日常应用启动。外盘暂时离线不等于原包失效；尚有操作未完成时，先按 AppPorts 的提示处理。只有身份名称的旧记录如何保留或清理，见[历史签名备份](/docs/archive/data-signing#backups)。

### 旧登录任务 {#login-signing}

当前版本在所有 macOS 上停用“开机自动重签名”，build 31 也已移除对应设置卡。更新后打开一次 AppPorts，让它处理旧登录任务；仅清理失败时，设置才显示“旧的登录重签任务尚未完全关闭，请重试。”，此时使用“重试”并保留错误信息。

## 后台接回 {#mount-agent}

挂载迁移会配置登录后的接回任务，用于将在线的数据卷接到原目录。它不替应用重签名，也不保证在所有登录应用启动前完成。

移动或更新 AppPorts 后打开一次，让它检查后台程序位置。系统需要管理员授权时，打开 AppPorts 完成操作。删除 AppPorts 前先[还原受管容器数据](/docs/restore#data)。

## 日志设置 {#logs}

可以开关日志记录、调整最大日志大小，在 Finder 中查看日志，或清空已有日志。需要反馈问题时，通过菜单栏“日志 → 导出诊断包”生成文件；导出不会自动发送。

提交前检查内容，说明系统版本、AppPorts 版本、发生的操作和界面提示。见[反馈问题](/docs/faq#feedback)与[隐私政策](/docs/privacy)。
