# 还原、接回与解除链接

先确认你想改变的是**存放位置**还是**访问入口**。开始前连接原来的外置盘，保存工作并退出相关应用；还原到本机还需要足够的本地空间。

## 选择正确的操作 {#choose}

| 目的 | 操作 | 完成后的数据位置 |
| --- | --- | --- |
| 把应用从外置盘搬回 Mac | 迁移回本地 | 真实应用回到本机。 |
| 把已迁移的数据搬回原目录 | 还原 | 数据回到本机原位置。 |
| 应用在外盘，只缺启动入口 | 链接回本地 | 真实应用仍在外盘。 |
| 数据在外盘，本地链接丢了 | 接回 | 数据仍在外盘，重建本地访问入口。 |
| 数据卷在线但未接到原目录 | 挂载 | 数据仍在外盘，恢复原路径的访问。 |
| 只移除应用的本地入口 | 本地列表的垃圾桶按钮 | 外盘上的真实应用保留。 |

## 把应用迁回本地 {#apps}

1. 在外部应用库选中应用，点击“迁移回本地”。
2. 核对本地目标。若存在同名真实应用或其他冲突，先处理提示，不要自行覆盖。
3. 等待复制、检查和收尾完成。
4. 从 Finder 或 Dock 打开应用，检查它现在使用的本地副本。

迁回应用本体不会自动迁回另行管理的数据。需要一起恢复时，继续处理下面的数据目录。

## 把数据还原到原位置 {#data}

1. 在数据目录或目录迁移中找到受管项目，点击“还原”。
2. 确认应用已退出、原外置盘在线、本机空间足够。
3. 等待 AppPorts 将数据复制回原位置并完成切换。
4. 打开应用检查内容和保存功能，确认最终状态。

还原完成后，AppPorts 会处理可安全清理的外部副本或专用卷。若提示仍有保留内容或未完成清理，先保留它们并按提示继续；不要把“能打开应用”当成全部收尾已经完成。

## 只恢复入口 {#reconnect}

应用显示“未链接”或只有外部副本时，选中后使用“链接回本地”。数据显示“待接回”时，核对外部目标后使用“接回”；“待挂载”的容器卷则使用“挂载”。

这些操作不把数据搬回内置盘。若本地原位置已经产生新内容，先确认两份数据的用途，不能用覆盖来强行恢复入口。

## 解除应用链接 {#unlink}

在本地应用列表中，找到已链接应用并点击行末垃圾桶按钮，悬停提示为“断开此链接并删除文件”；孤立链接也可右键选择“删除孤立链接”。这会移除 AppPorts 管理的本地入口，外置盘上的真实应用保留。**它不是数据目录的还原操作。** 之后仍可重新“链接回本地”。

删除 AppPorts 前，先还原仍由它管理的容器数据；否则自动挂载任务可能失去所需程序。中断、离线或目标冲突的处理见[常见问题与排查](/docs/faq)。

## 处理未完成操作与保留副本 {#recovery}

在“任务中心”打开需要处理的任务，点击“处理异常”，先看当前迁移记录。退出关联应用，接好并解锁原盘；权限不足时使用“检查权限”，再重试。重试范围以面板列出的项目为准，“重试待处理操作”可能涉及多条记录。

| 数据异常面板中的选择 | 实际作用 |
| --- | --- |
| 重试／重新尝试清理 | 重新检查并继续相应操作；不会强制删除有差异的旧文件。 |
| 稍后处理 | 暂停自动处理，保留文件，之后可以主动重试。 |
| 打开旧副本 | 在数据已切换、位置核对通过时查看保留内容。 |
| 保留副本并结束清理 | 仅在数据已切换后提供；停止自动清理和异常提醒，旧副本仍占空间，可再打开或单独重试清理。 |

主体迁移完成但旧副本尚未清理时，任务仍可能显示“需要处理”。后台完成了旧现场清理，也不能据此把原迁移判为成功；请结合目录实际状态核对。移除任务历史不会解决这些记录。

应用异常面板另有“重试处理”“忽略错误结束任务”和“忽略错误强制回迁”。优先重试正常处理。“忽略错误结束任务”只把原记录归档为未完成并保留文件；**“忽略错误强制回迁”不进行内容校验**，会在复制成功后替换本地入口，保留外盘原件及已有本地副本，原记录仍归档为未完成。只有理解确认框含义并愿意自行检查结果时才使用，不能视为正常还原成功。
